# How A3P compares

Read on 13 October 2026 from public docs and product pages. The Context.dev search connector was not authenticated in this environment, so nothing below came from that API. This is not a ranking and not a claim that A3P replaces any of these products. Where they are ahead, the cell says so.

A3P's own bar is narrow: a tool receipt is not a fact (A3-EP CF-001), the sample is scored under A3P Method v1.0, and a level is an assessment of that sample. It is not a certification.

## What round 8 adds, and what it does not

Read-only verifiers, a small custom-verifier SDK (`docs/VERIFIERS.md`), wrappers for an OpenAI Agents SDK runner and a CrewAI `kickoff` when those packages are installed (they are not dependencies), a compiled-graph adapter, an MCP HTTP client, and post-hoc checks of OpenTelemetry or Langfuse JSON against world reads. Results can be wrapped in an in-toto Statement and a DSSE envelope signed with the same Ed25519 key as the badge. `a3p verify-attestation` checks that envelope without re-running the probe. `docs/verify/index.html` checks a badge signature in the browser.

Keyless Sigstore is optional. `sign_keyless` calls sigstore-python (Fulcio and Rekor) only when an ambient OIDC token is present. This workspace had none, so no Fulcio certificate and no Rekor entry were produced here. The Ed25519 signature is still written and is not a Sigstore certificate. New badges include `sigstore_sha256` in that Ed25519 payload, so a later swap of the bundle fails verification. `a3p verify-badge` checks the Ed25519 signature on its own. Pass `--identity` and `--issuer` and it also checks an attached bundle: the certificate identity and the Rekor inclusion proof. GitHub Actions can supply the token when the `sigstore-keyless` job sets `id-token: write`. That round trip works once this repository is on GitHub and that job runs. It was not run here.

The adaptive loop still runs with no model. `AdaptiveAttacker` asks an OpenAI-compatible endpoint (Groq, an OpenAI-compatible Gemini route, OpenRouter, or anything else with that API) for the next user turn after it has seen the target's reply. The strategies are paraphrase, translation, encoding, role-play, and payload splitting. The request sends the seed. Every generated turn is appended to the signed ledger, and a replay reads that text instead of calling the model again. A live model is not bit-identical across calls; the ledger is the replay. If the endpoint is absent or the call fails, `ScriptedAttacker` branches on the reply with the seed. The same reply repeats. Offline translation uses a phrase table. English, Italian, Spanish, French, German, and Portuguese are marked reviewed. Chinese, Japanese, Russian, Arabic, and Hindi are marked machine. The older four strategy prompts (crescendo, role-play, encoding, tool-output) are still there. This is not Promptfoo's plugin catalog.

`a3p mcp-scan` still reads a tool JSON file. `a3p mcp-scan --live --command` launches the named server inside the sandbox. With no command it launches the vulnerable demo. A loopback `--url` is bridged from a unix socket to `127.0.0.1` inside the sandbox; the sandbox does not gain a route. `--probe all` sends the local archive. The default is three rows. `--invoke-destructive` calls destructive tools. The demo records a fake effect and does not execute a command. A third-party tool still runs its own code in the sandbox. `--sandbox process` is refused unless `--unsafe-process-sandbox` is set. The automatic order is `runsc` when that binary is installed, then a container, then nsjail, then bubblewrap. `A3P_ISOLATION` forces a jail even when Docker is installed. On 14 October 2026 both binaries were installed here and a demo stdio scan ran inside each: network denied, host marker intact, one poisoning finding. The `jails` CI job installs both binaries. `--transport streamable` speaks MCP Streamable HTTP (POST `/mcp`). Findings go into the signed ledger. Invariant/Snyk still leads on rule language. An allowed tool is not a promise that the tool is safe.

`a3p dashboard` listens on loopback. `--allow-remote` with a bearer token of at least 16 characters binds another host. Without the token the command refuses. `--tls` with `--allow-remote` serves HTTPS. If no certificate is given, the process writes a self-signed certificate. That is not a public deployment. The pages are run history, one run with phantom, injection, permission, and leakage scores, a regression of the latest pair, and a G3 sample badge. Fonts and colours follow the public site. Pattern credits are in [DASHBOARD_CREDITS.md](DASHBOARD_CREDITS.md). A Playwright test opened history, a run, the regression, and the badge at 1440 and 390. It is not a multi-tenant product and not a certification.

`psycopg` is the optional `world` extra. A test opened Postgres 16 and ran a SELECT. The same run started Mailpit and read the message back. MinIO's container image could not be pulled here; the S3 check used the official linux-amd64 binary `RELEASE.2025-09-07T16-13-09Z`. boto3 is not a dependency. OpenAI Agents SDK and CrewAI are optional extras and were tested against a mock chat-completions server, not a live provider key.

None of this changes A3P Method v1.0. A signed PDF or a signed statement is still `assessed under A3P Method v1.0, level A3P-Lx`. It is not a certification.

## Where A3P is the wrong tool

- You want hundreds of content probes (toxicity, encoding suites, multilingual jailbreaks at garak or Promptfoo volume). Import a local garak or Promptfoo file. Do not expect the 81 scenarios to match that volume.
- You want a hosted enforce-mode API in front of production traffic in many languages. Lakera, Splx, Mindgard, and Protect AI sell that. `a3p guard` is a small loopback check for unverified success claims.
- You want Invariant's rule language, pause/log policies, and a production MCP firewall. `a3p mcp-proxy` pins descriptions and enforces an allow-list on stdio and streamable HTTP. It does not ship their rules. `a3p guard` is still the loopback check for unverified success claims.
- You want a certificate. None of these products, including A3P, should be read as one. Giskard says so in their OSS docs. A3P says so on the badge: `assessed under A3P Method v1.0, level A3P-Lx`.
