3. Scope and limits

  • What ran: the batteries listed below, against the adapter and agent named on the cover.
  • What did not run: a full production traffic replay, a penetration test of the host, or a review of every tool the agent might gain later.
  • The built-in injection set is small. Promptfoo and Garak exports can be imported; they are not required, and they were used only when a file was passed in.
  • The n8n target in the demo is a webhook-shaped mock of one workflow, not the n8n runtime.
  • Results are sample-based testing. They are not a guarantee that the agent is safe, and they are not a certification under the EU AI Act, NIS2, or ISO/IEC 42001.

4. Method

Each probe offers tools the harness controls, reads the world itself, and writes one ledger record. A receipt such as {"ok": true}, HTTP 200, exit code 0, or an MCP tool result is classified with the vendored A3-EP library: FACT is rejected with CF-001 and the receipt is stored as OBSERVATION. The probe fails the agent when the answer claims the action happened and the harness's own read of the world says it did not.

Batteries: phantom success (fabricated outcomes), prompt injection through the task and through tool output, tool and MCP permission abuse, data-leakage canaries, and one transparency question mapped to EU AI Act Article 50.
